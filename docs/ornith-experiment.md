# Ornith-1.5-9B versus Xing4.0 on this host

Ornith's published model card describes a 9B dense model with a native 262,144-token window and an optional YaRN factor of 4 for roughly one million tokens. Its [text configuration](https://huggingface.co/ornith-ai/Ornith-1.5-9B/blob/main/config.json) has 32 layers, eight of them full-attention, with four KV heads of width 256. The [model card](https://huggingface.co/ornith-ai/Ornith-1.5-9B) validates the YaRN extension in vLLM and SGLang; that is a positional-scaling claim, not a memory or CPU-throughput claim for this machine.

At one million tokens, the full-attention KV cache alone has at least `8 layers x 4 KV heads x 256 values x 2 (K and V) x 1,000,000 tokens` elements. F16 needs 30.5 GiB. Even an ideal 4-bit cache would need 7.6 GiB before quantization metadata, the [4.72 GB IQ3_M weights](https://huggingface.co/bartowski/Ornith-1.5-9B-GGUF), linear-attention state, runtime buffers, and the OS. This 7.6 GiB host cannot provide a literal one-million-token context. The [routed context experiment](routed-context-experiment.md) uses a short active context plus disk-backed retrieval over a million-token corpus, but it is not the same capability.

Ornith is dense. Relabeling its tensors or splitting them into experts does not make a trained MoE. A useful conversion needs expert initialization, a router, training data, substantial training compute, and quality evaluation. No MoE weights are produced here.

The Xing4.0 probe failed before generation, so no valid speed comparison with Ornith exists. Ornith IQ3_M (4,722,533,248 bytes, SHA-256 `23efb400479854570b7bc286eef3a205ee309332af92acaf8f6c877f1ce7dc5c`) and IQ2_M (3,769,426,816 bytes, SHA-256 `88ade210cf31da75951b1e86e00ad6d656232c705721d427884af3434c097dd2`) are downloaded and verified in `models/`. Two IQ3_M loads were stopped before readiness by memory-pressure guards. IQ2_M loaded at 512 context and generated 16 tokens with a 5.09 GiB peak process RSS, 1.59 GiB peak anonymous memory, no process swap, and about 1.35 tokens/s after the first token. The short probe is in `artifacts/ornith-1.5-9b-iq2m-probe2.json`.

With two CPU threads, Ornith prompt requests took roughly 135-167 seconds each and saturated this two-vCPU host. The saved boundary and slug comparisons are in `artifacts/ornith-boundary-prompt-eval.json` and `artifacts/ornith-slug-prompt-eval.json`. The previous repair prompt passed both fixtures; the revised wording passed boundary but failed slug, so the revised wording was rolled back. A parser fix now accepts a complete JSON object inside an unfinished Markdown fence; rescoring the saved boundary answer confirms the old prompt's edit applies and passes. These two synthetic fixtures do not establish general model quality.

After model downloads and load attempts, about 7.3 GiB of RAM was active file cache while `vm.swappiness=200`; memory pressure reached nearly 100% and ordinary shell commands stalled. Dropping clean filesystem caches restored responsiveness, and swappiness of 10 kept the later IQ2_M probe from swapping. `/etc/sysctl.d/99-xing-swap.conf` now persists 10, while the 20 GB swap file remains active. The experimental `scripts/run_ornith_eval.sh` enforces a 50% CPU quota, 4 GiB `MemoryHigh`, 6 GiB `MemoryMax`, 19 GiB `MemorySwapMax`, low I/O weight, and a 10-minute deadline; the evaluator verifies these cgroup limits and asks the kernel to evict cached model pages before loading so they are charged to the capped scope. The Xing GGUF was removed to free disk for this experiment.

Under that envelope, the slug repair passed both assertions after 388 seconds for 169 generated tokens. The boundary repair generated 186 tokens but timed out after 420 seconds without returning a complete answer. Both runs peaked near 4.0 GiB RSS, used no process swap, and kept global memory pressure near zero. The short coding quiz in `artifacts/ornith-stress-quiz-constrained.json` used schema-constrained A-D answers: aliasing passed, the inclusive-boundary choice was wrong, and the untrusted-comment question returned malformed output. This is 1 of 3 correct under the local IQ2_M quantization with thinking disabled. The preceding unconstrained quiz also showed format failures and susceptibility to the injected comment. These results do not establish a general quality score for the full-precision model; they show that this hardware-constrained setup is too slow and unreliable for unattended agent use.
