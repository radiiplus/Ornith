# Xing4.0-29B-A4B architecture

Checked 2026-10-29 UTC against the publisher's [config](https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B/blob/a32a2e99b5877c6b7ad16e9954ec08488bcc5fa2/config.json), [reference implementation](https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B/blob/a32a2e99b5877c6b7ad16e9954ec08488bcc5fa2/modeling_xing4_0.py), [model card](https://github.com/XingChen-AGI/Xing4.0-29B-A4B), and [safetensors index](https://huggingface.co/XingChen-AGI/Xing4.0-29B-A4B/blob/a32a2e99b5877c6b7ad16e9954ec08488bcc5fa2/model.safetensors.index.json). No weights were downloaded.

The publisher describes **29B total and approximately 4B active parameters/token**. The BF16 safetensors index reports 62,438,573,536 weight bytes, or about 31.2B BF16 scalar equivalents; this includes the extra MTP head and is not a direct count of inference-active parameters. The architecture is `xing4_0` / `Xing4_0ForCausalLM`, with 40 decoder layers, 3584 hidden size, 131072 vocabulary, and untied embeddings. `first_k_dense_replace=2`: the first two layers use dense 9216-wide FFNs; subsequent layers use MoE FFNs with expert intermediate width 1024. The config specifies 64 routed experts, four selected per token, and one always-on shared expert. The router computes sigmoid scores, adds correction bias for top-k selection, normalizes selected weights, and scales them by 2.0. These details matter for compatible inference and conversion.

Attention uses 32 query and 32 KV heads in the reference implementation, Q LoRA rank 768, latent KV rank 512, non-RoPE Q/K head width 128, RoPE width 64, and value head width 128. Native configured context is 262144 tokens, with YaRN RoPE scaling from an original 4096-token setting; the publisher claims extension to 512K, which is not the configured default. `hc_mult=4` manifold-constrained hyper-connections expand and mix residual streams. One NextN/MTP prediction layer is present. A faithful engine must preserve MLA, mHC, MoE routing, RoPE scaling, and the normal output head; MTP may be unused for ordinary autoregressive generation but must not corrupt tensor mapping.

The reference Transformers code uses `AutoModelForCausalLM` remote code (`configuration_xing4_0.py`, `modeling_xing4_0.py`, `tokenization_xing4_0.py`) plus `chat_template.jinja`, tokenizer assets, PyTorch, and Transformers. The config records `transformers_version=5.14.1` and custom `auto_map` entries. The publisher's example uses `trust_remote_code=True`, so review and pin the code before execution. Its attention code expands latent K/V into per-head K/V *before* `DynamicCache.update`; this is important for memory estimates. The [Xing4.0 llama.cpp port](https://github.com/shuxiaoqiong/llama.cpp/blob/xing4_0-port/src/models/xing4_0.cpp) instead constructs compressed K of width 576 and V from the 512-wide latent tensor.
